## 2024-08-18 - Participant Data Exfiltration via Pickled Models
**Vulnerability:** The `TwinLiteRetriever` class stores the entire raw training dataset in `self._reference` in order to return actual matched participant rows. When this model is exported to disk via `joblib.dump` (in `scripts/export_models.py`) for potential external upload, it silently includes all participant-level features and identifiers (PHI), creating a major data exfiltration vector.
**Learning:** Classes that memorize training subsets (k-NN, retrievers, case-based reasoners) are extremely dangerous when serialized because the artifact becomes a Trojan horse for the dataset. Relying on "synthetic only" workflows during dev often masks this risk if the architecture allows real data exports in production.
**Prevention:** Implement Python's `__getstate__` for any machine learning class that caches DataFrames to explicitly drop, hash, or anonymize sensitive PII/PHI columns (like `participant_id`) before serialization.
